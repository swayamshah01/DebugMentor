# DebugMentor

DebugMentor is a focused DSA practice platform that helps a learner test complete
console programs, understand failures, and request progressive AI hints.

The application deliberately has two grading actions:

1. **Run** executes the current program against one selected visible test case.
2. **Submit** executes the program against every visible and hidden test case and
   saves the final result to the learner's profile.

There is no free-form execution mode and no function-only judge contract. Every
solution is a normal program with a `main` entry point that reads standard input
and prints standard output.

## What Is Included

- Pattern-based problem explorer backed by PostgreSQL
- 15 curated DSA problems across 6 patterns
- 60 real test cases, with 2 visible and 2 hidden cases per problem
- Complete-program starters for Python, JavaScript, Java, and C++
- Monaco code editor with a single file per problem
- Compile, runtime, timeout, empty-output, and wrong-output reporting
- Final submission history, pattern progress, pass rate, and earned badges
- JWT authentication with unique usernames and emails
- Progressive, submission-specific hints generated by Gemini
- Alembic-owned schema and idempotent curated-content synchronization

## Product Flow

1. Register or sign in.
2. Choose a DSA pattern and problem.
3. Select a visible test case.
4. Write a complete program in the editor.
5. Use **Run case** to check only the selected visible case.
6. Use **Submit** when ready for all visible and hidden cases.
7. For a failed submission, open **Hints** and reveal help progressively.
8. Review accepted problems and failure patterns on the profile page.

## Program Contract

Each language uses its conventional entry point:

- Python: `def main()` plus the `__main__` guard
- JavaScript: `function main()`
- Java: `public static void main(String[] args)` in `Main.java`
- C++: `int main()`

The judge sends each test case through standard input. The program must print only
the requested answer. Output comparison normalizes whitespace and supports common
JSON-style arrays, booleans, integers, and floating-point values.

## Requirements

- Python 3.11 or newer
- Node.js 18 or newer
- PostgreSQL
- Python available for Python submissions
- Node.js available for JavaScript submissions
- JDK with `java` and `javac` for Java submissions
- `g++` with C++17 support for C++ submissions

A Gemini API key is optional for grading, but required to request hints.

## Backend Setup

From the repository root:

```powershell
cd backend
python -m venv venv
.\venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
Copy-Item .env.example .env
```

Edit `backend/.env` with your PostgreSQL URL and a private JWT secret:

```env
DATABASE_URL=postgresql://postgres:your_password@localhost:5432/debugmentor_db
SECRET_KEY=replace-with-a-long-random-secret
DEBUG=False
SQL_ECHO=False
CORS_ORIGINS=http://127.0.0.1:5173,http://localhost:5173
AUTO_SEED_CURATED_CONTENT=True
EXECUTION_TIMEOUT_SECONDS=5
COMPILE_TIMEOUT_SECONDS=10
GEMINI_API_KEY=
GEMINI_MODEL=gemini-2.5-flash
HINT_TIMEOUT_SECONDS=30
```

Apply the schema and start the API:

```powershell
python -m alembic upgrade head
python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

The startup lifespan synchronizes curated content when
`AUTO_SEED_CURATED_CONTENT=True`. The seed is idempotent, so restarting the API
does not create duplicate problems or tests.

- API health: [http://127.0.0.1:8000/health](http://127.0.0.1:8000/health)
- API docs: [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs)

## Frontend Setup

In a second terminal, from the repository root:

```powershell
cd DebugMentor
npm install
npm run dev
```

Open [http://127.0.0.1:5173](http://127.0.0.1:5173).

The frontend defaults to `http://127.0.0.1:8000/api`. To use another API URL,
set `VITE_API_BASE_URL` before starting Vite.

## Main API Routes

- `POST /api/register`
- `POST /api/login`
- `GET /api/users/me`
- `GET /api/patterns`
- `GET /api/patterns/{pattern_id}/problems`
- `GET /api/problems/{problem_id}`
- `POST /api/run`
- `POST /api/submit`
- `POST /api/hint`
- `GET /api/profile/{user_id}`

`POST /api/run` requires a visible `test_case_id` and never stores a submission.
`POST /api/submit` grades the full official set and stores one submission record.
Hidden inputs, expected values, and actual values are never returned to the client.

## Hints

Hints are generated only after a failed final submission. The model receives the
problem statement, input/output contract, submitted code, and visible failure
evidence. It does not receive hidden test values.

The three levels are:

1. A precise place to investigate
2. A more specific reasoning or implementation direction
3. A complete corrected console program for the selected language

Generated hint bundles and the current revealed level are stored with the
submission. There are no generic hardcoded hint fallbacks: if Gemini is not
configured or unavailable, the API returns a clear service error.

## Adding Problems

Curated problem content lives in `backend/seed_data.py`. A problem must include:

- a unique slug and pattern
- a clear statement and input/output format
- constraints and examples
- starter programs for all four languages
- visible and hidden stdin/stdout test cases

After changing curated content, restart the backend or run:

```powershell
cd backend
python seed_data.py
```

The synchronized content becomes available to every user because it is stored in
PostgreSQL, not in the browser.

## Execution Safety

The current subprocess runner is suitable for local development and classroom
demos. It enforces timeouts, limits Python imports, and uses isolated temporary
directories, but it is not a production security boundary. Before exposing public
code execution, move execution into locked-down containers or a dedicated sandbox
service with CPU, memory, process, filesystem, and network limits.

## Troubleshooting

### The explorer shows no questions

Confirm PostgreSQL is running, apply `python -m alembic upgrade head`, and restart
the backend so curated content can synchronize.

### The frontend cannot reach the API

Confirm both local origins are present in `CORS_ORIGINS`, then restart the backend.

### Java or C++ reports a compiler error before user code runs

Check the local tools:

```powershell
java -version
javac -version
g++ --version
```

### Hints are unavailable

Set `GEMINI_API_KEY` in `backend/.env` and restart the API. Run and Submit continue
to work without Gemini.
